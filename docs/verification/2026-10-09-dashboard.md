# KotoriダッシュボードとWindows表示（2026-10-09）

カード61、PR147。設定ツールをKotoriという入口に統一し、実測値を確認できる最初の画面を追加した。
公開済みv1.1.0-rc.3には含まれない。元ソース、EXE、パッチ、画像のSHA-256は同名JSONに固定した。

## 変更と測定範囲

- AI状態・モデル名・計算量、PCと変換サーバーのCPU・RAMを2秒ごとに更新する。
- 大きな数値、細いゲージ、直近60秒までの実測CPUグラフ。未取得は「未確認」またはダッシュ記号。
- 状態ファイルのPID・起動時刻・実行ファイルを照合。別プロセスや古い記録を動作中と扱わない。
- 新しい状態更新は非同期ワーカーで実行。累計時間はSpaceの待ち時間やGPU使用率と呼ばない。
- Windowsフォントのフォールバックを使い、標準ウィンドウ枠とQtのタブ/ボタンを保持。
  選択欄の矢印を隠していたdrop-downスタイルを除去し、品質・モデルの標準矢印が表示されることを確認。
- 開発支援の固定Stripeリンクをダッシュボード・AI設定に配置。クリックでブラウザーを開く。
  READMEと使い方案内にもリンクを追加し、ローカル推論と外部リンクの動作を明記した。

GUIテストは隔離プロファイルとモックのクライアントを使い、普段使いのIMEに接続しない。
Kotoriという実際のwindowTitle、初期タブ、AI設定への移動、CPU/メモリ/ゲージ/履歴更新、設定保存が呼ばれないこと、
支援ボタン2個とautoDefault無効、別プロセスの状態拒否、ダッシュボードとAI設定の状態表示一致を確認した。
画像は本物のQt画面をWindows QPAで描画して保存したもの。PCの数値は実測、AIは接続しないため未確認と表示される。
通常/150%で日本語・数値・余白・選択欄・スクロールを目視した。画像はJSONのパスにある。

実辞書/実モデルの別セッションではloading→llm、正しいPIDと起動時刻、計算量の更新を確認した。
RTX 3060、zenz-v2.5-small-q8_0とTinySwallow Q5。zenz work=132ms/calls=42、llm work=82ms/calls=2。
これは計算量の記録確認であり、変換精度・Spaceの待ち時間・入力中の補正の受け入れを意味しない。

## 初回確認からの修正

最初のoffscreen画像では日本語の字体が表示できなかったため、Windows QPAで取得し直した。
後続の状態一致テストで、AI設定のラベル名を注記用の名前で上書きしていたため、null参照のSEH 0xc0000005が発生した。
注記をQtのpropertyに分離し、名前を維持。テストにもnonnull確認を加え、上表の最終テストで成功した。
失敗ログは `dashboard-final-tests-20261009.log` として残した。以前の成功記録をこの失敗や最終ソースの証拠として使わない。
