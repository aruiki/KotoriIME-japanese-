# 生成補正と実モデル内容の対応付け（2026-10-09）

ZenzScorerがモデル読み込み前にSHA-256を取得し、モデルの所有期間中はWindowsの読み取り共有ハンドルを保持する。
書き込み・削除/置換と競合するファイルを識別不能とし、識別不能でも既存の採点を使うが自由生成補正は採用しない。
識別は生成補正を明示した非同期ロードだけ。通常の同期打鍵にはハッシュや追加のディスクI/Oを入れない。
KOTORI_LM_PRELOAD=0の同期評価では識別も自由生成補正も無効。ワーカーは設定を初期化した後に開始する。

補正の出所は入力世代・設定キー・モデルロード世代と、実際に採点/生成したzenzとLLMのSHAを持つ不変の識別情報。
保存・再取得・適用直前の各境界で同じ識別情報を照合する。モデルの交換、同世代の別識別情報、識別の欠落を拒否する。
モデルは変更せず、同梱モデルの内容を開発ログのSHAと照合した。具体的な値は同名JSON。

Windowsのファイル識別6ケースと、追加した保存/表示境界2ケースを含むLM31ケースが成功。
Sessionテストも成功、session_handler_mainとconverter_mainはbuild成功。
実ファイルの既知SHA・複数ブロック・日本語パス・同時読み取りと、保持中の上書き/削除/rename拒否を確認。
所有者解放後には書き換え可能となり、別内容のSHAへ変わる。

最終の同一EXEで生成OFF/ONを比べ、OFF初回「足を炒めたので病院に行きます」、ON初回「足を痛めたので病院に行きます」。
ONはSpace後も一致し、TestSendKeyのコピー後も保持。取消・AI無効・保護欄・シークレット後の古い補正を拒否した。
