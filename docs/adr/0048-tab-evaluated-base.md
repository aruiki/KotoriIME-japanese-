# ADR0048: Tabの先頭を評価済み本文か強い続き予測にそろえる

状態: ローカル試作・検証中。2026-10-09。カード63、ADR0040・0042・0047。

通常100文の検証で初回表示とSpaceは正しくても、Tabで「１０時→従事」、
「戻ります→戻りマスター」、語尾の「ますます」「覚えるる」などが出た。
TabのLLMだけの平均点で、初回のZenz/LLM評価済みの本文が押し下げられていた。
特に数字は「読みのかなに数字がない」という条件で、正しい変換も順位づけから外していた。

初回の評価済み文を、既存キャッシュの世代・設定・モデル・読み・文脈の検査を経て再利用する。
Tabでその本文を先頭へ置き、本文をそのまま保持するcan_leadかつ読み照合済みの続きだけが先頭を置き換えられる。
平均点の閾値を緩めたり、全候補の数字を許可したり、同期の生成を追加したりしない。
未評価の入力では従来のTabを維持し、弱い予測や別解も一覧へ残す。

この方針は強い予測がない時にTabの先頭が本文になるため、表示する続きの量は減り得る。
初回とTabの整合性と、本文を勝手に崩さないことを優先する。実TSFと全体の予測精度は別に確認する。

## ローカルの結果

LM44・Session189・Engine84・モデル識別6の関連テストが成功（変更のない2ターゲットはBazelキャッシュ）。
実モデルの固定10文は補正OFF/ONとも初回/Tab/Space一致10/10。数字・マスター化・読み内の意味変更を抑えた。
CPU強制の2文で入力維持、最終EXEの制御例で生成補正の初回/Space一致を確認。
「おはようございます」は今回の初回表示には採用されておらず、強い続き予測の実モデル受け入れを完了とは扱わない。
源ソース・実行ファイル・モデル・データ・ログ・パッチのハッシュは同日のtab-consistencyの記録。
