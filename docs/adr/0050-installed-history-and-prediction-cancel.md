# 0050: インストール済みの履歴と予測取消しによる補正の消失

- 日付: 2026-10-10
- 状態: 採用。ローカル検証済み、新MSIのWindows実入力は未検証。
- 関連: 0040、0049、カード64

## 問題と証拠

利用者はBUILD6331を導入・再起動後も「あしをいためた」が「脚を炒めた」と報告した。
稼働中serverのPID、実行パス、TIP32/64の登録先、インストールされた本体・モデル・実行環境の
ハッシュを確認。6331MSIと一致し、Standard/LLM、入力中予測・生成補正は有効だった。
既存Mozc IPCの専用セッションでも初回/Space1が「脚を炒めた」。ユーザーの入力確定は行わない。

同じローカルEXEで、実際の学習履歴を試験専用ディレクトリへコピーし比較した。
履歴OFFは「足を痛めた」、履歴ONは「脚を炒めた」。AIの採点では痛めたが優勢だが、
後続のUserSegmentHistoryRewriterが過去の文節履歴を先頭へ昇格していた。
従来CLIの履歴既定OFFではこの失敗を取り逃がした。

同じインストール済みserverでは「ちょと待ってください」が初回/Tabで補正されても、
Escの直後のSpaceで補正が消えた。予測表示だけの取消しが入力世代を更新し、
同じ未確定入力の補正結果まで無効にしていた。

## 決定

1. 履歴の並べ替えは、先頭がkotori_ai_evaluatedの場合に先頭を保護し、学習した別候補をその後ろへ並べる。
   AIが評価していない場合は従来の学習順位を維持。履歴削除や個別の語の禁止で回避しない。
2. Sessionの予測取消し専用メソッドを追加する。PREDICTIONかつ読み・カーソル・欄・設定が同じときだけ
   入力世代を保つ。編集、通常のCancel/Reset、確定、保護欄、設定変更による無効化は維持する。
3. first_display_compare.pyは履歴rewriterを明示的に有効にする。通常の試験で実プロファイルを使わない。
   今回の原因確認だけ、本人の許可範囲で履歴コピーを作り、原本を変更・公開しない。
4. インストール済みIPCプローブは稼働PIDと実行ファイルのハッシュで識別する。
   WindowsのIPC広告版はクライアント側の版で補完される場合があるため、版の証拠にしない。
   モジュールがロードされているだけでTSF入力を検証したとも扱わない。
