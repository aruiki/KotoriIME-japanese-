# 0052: 設定保存の結果を明示して失敗時の変更を保持する

- 日付: 2026-10-10
- 状態: 採用、ローカルWindows Qt検証済み。更新MSI作成へ。
- 関連: 0039、カード57/65、利用者の「適用ボタンは全く画面変化がないので不安」

## 問題と判断

既存Updateは設定サーバーの保存失敗を通知した後もtrueを返し、OKで閉じる可能性がある。
Applyなど保存ボタンにも汎用変更通知がつながり、保存直後の未保存表示へ戻ることがある。
全タブ共通のステータスを設け、サーバーからの成功応答でだけ「設定を適用しました」と表示する。

毎回成功ダイアログを閉じる方式では入力操作が増えるため、標準のQLabelで結果を残す。
色だけに頼らず、保存状態のアクセシブル名も付ける。
保存中にはApplyを無効にして進行中の文章を描画し、失敗時には再度有効にする。
失敗時はUpdate=falseで画面と編集値を保持。Windowsホットキー保存の部分失敗も表示する。
変更していないWindowsホットキー設定は書き直さない。

ダッシュボードも測定が始まるまで空欄にせず、確認中/計測中/—を表示する。
同期待ちの新たな測定や通信は追加しない。

## 検証と配布

修正前の状態ラベル不在FAIL、修正後4テストPASS（保存成功/失敗と再試行、既存ダッシュボード/古い状態拒否）。
100/150/200%のWindows Qtの非表示描画で日本語、保存表示、ボタン、スクロールを確認した。
設定サーバーはmockであり、利用者の設定は書き換えていない。
本体の導入確認は6332の実際のサーバーIPC。Windowsアプリの候補描画とは区別する。
詳細: ../verification/installed-6332-and-settings-feedback-20261010.md。

ローカルでパッチ再生成と全3パッチ適用を確認。版を3.34.6333.100へ上げて別MSIを作成する。
利用者は全buildのローカル化、公開後に自身で導入して実機デバッグする順序を指定済み。
その順序を引き継ぎ、未署名・実入力/削除の未確認を公開ノートへ明記する。
6332の公開バイナリ・ソース・失敗/検証原票は保持し、同版MSIを改変して差し替えない。
