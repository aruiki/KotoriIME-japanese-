# 0053: 補正済みの読みで別候補を作り、元の入力への復帰を保持する

- 日付: 2026-10-10
- 状態: 採用（ローカル変換検証済み、実機入力の受入れは継続）

導入6333の専用IPCで「ちょとまってください」は最初/Tab/Space1で直るが、Space2で補正前の読みの候補へ戻る。
検証済みLLM補正の機械的な読み修正だけを候補の一時情報として渡す。同音漢字の修正には付けない。
Space変換では同じ入力世代/保護欄を確認し、skip_slow_rewritersでMozcの辞書候補だけを作り、先頭のAI結果の後ろへ並べる。
入力composerと候補の消費キーは元のまま。追加候補は学習しない。元の候補は「補正前の読み」と明示して保持する。
AIモデル/辞書の種類、品質設定は変えない。新しい同期推論を入れない。
通常入力・同音語・AI無効には追加処理を行わない。辞書変換失敗時は既存候補を維持。
Windows実画面の確認と正式版の判定は、ローカルCLIやコンポーネントテストと分ける。

4テスト対象と実モデル18例が通過。Standardの200問は91.5%を維持。
正しい読みの候補を挿入しても、入力composer・確定処理・履歴原本は変えない。
元の下位候補や保護ユーザー辞書には未採用補正の情報を付けない。
