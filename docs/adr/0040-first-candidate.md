# 0040. 入力中の最初の候補を評価してから表示する

- 状態: 実装・検証中。配布版への反映はまだ。
- 日付: 2026-10-08
- 関係: カード51、ADR0039、REQ-14-2

## 依頼

Space を押す前の誤変換を最優先で改善する。採用条件を満たした続き予測も Tab を押す前に表示する。
候補欄は Windows になじむ控えめな見た目にする。

## 変更

読みは直ちに表示し、候補欄は最初の AI 評価まで待つ。キー入力内でモデルを呼ばない。
遅延コールバックでも推論を待たず、Mozc が作った文候補と設定のコピーをワーカーに渡す。
評価結果は読み・文脈・モデル設定が一致するときだけ取り出す。内部候補は維持し、待つ間も Space / Tab を受け付ける。

モデル準備中・ロック取得失敗・時間切れを「補正不要」としてキャッシュしない。
元の文と同じ結果でも評価済みかを区別する。評価できなければ最大5回の更新後に通常候補へ戻す。
AI無効・シークレットモード・パスワード欄では、この待機を行わない。既存のモバイル混合変換も対象外。

続き予測は、読みの一致に加えて、1トークンあたりの log P が -1.0 以上、次点との差が0.5以上のものを
初回表示の対象にした。これは**正解確率ではなく暫定の採用条件**であり、予測セット全体での適合率・表示率の評価が必要。
条件を満たした候補を、後から通常変換で押し下げない。明示的な Tab の予測候補は従来どおり扱う。

Windows描画の余白・色・番号の太さを変更。通常の候補一覧に文字種候補をまとめる設定を既定にし、
「そのほかの文字種」という副候補欄を既定で使わない。既存の明示的な設定は維持する。
実描画を100%・200%でBMPへ出す `kotori_candidate_snapshot` を追加した。実行中のIMEへ接続しない。

## 確認と限界

詳細は `docs/verification/2026-10-08-first-candidate.md`。
実モデルで「あしをいためたので」の最初の表示が「足を痛めたので」となり、Space後も一致した。
これは1例の動作確認であり、全体精度の向上やAJIMEE-Benchの維持を示すものではない。

自由な文章補正をLLMに生成させる機能と、カタカナから英語の綴りを作る機能はこの変更には含めていない。
既存のzenz生成・LLM採点・1編集の打ち間違い補正を入力中にも使う段階である。
TSF経由の実アプリ確認、予測の採用条件の検証、精度・負荷の前後比較、CI/MSI検証が終わるまで完成扱いにしない。
