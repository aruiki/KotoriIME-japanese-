# 51: 最初に見える候補の補正・予測と候補ウィンドウ

- 依頼: メンテナ、2026-10-08。初回表示の品質が最優先。
- 関係: ADR0039、0036、REQ-14-2。既存の保護フィールド・入力応答・学習の保護を維持。

## 目的
Space/Tabを押す前から補正と確信度の高い予測を表示する。
カタカナ語の英語候補を追加し、候補の見た目を控えめにする。

## 手順
1. 既存の遅延更新と初回候補、Tab予測の評価・採用条件を調べる。
2. 未評価のMozc候補を先に見せる挙動を改め、入力を止めず更新する。
3. 文の補正・誤入力訂正の生成と選択を入力中にも反映する。
4. 英語候補と候補ウィンドウの表示を整える。「そのほかの文字種」は低コストなら除去。

## 検証
- 初回表示・続き予測・世代の古い結果・AIなし・保護フィールドの回帰テスト。
- 「あしをいためたので」、誤入力、英語語彙の実出力と応答時間。
- 精度・負荷の前後比較、Windowsのビルド・UI確認。

## 完了条件
- [ ] 初回表示に未評価の誤変換を先出ししない。
- [ ] 補正・予測の採用条件を検証する。
- [ ] 英語候補と候補UIを確認する。
- [ ] 数値・未検証範囲を記録し、CIを確認する。

## 2026-10-08 の実装記録（開発中）

- 初回候補を評価まで待ち、評価をワーカーへ分離。最大5回で通常候補へ復帰。
- モデル未準備の結果をキャッシュする不具合を修正。
- 続き予測の暫定採用条件と、通常変換で押し下げない処理を追加。
- Windows候補欄を変更。実描画の100%・200%画像を確認。
- 6テストターゲットPASS。実モデルで「足を痛めたので」を最初に表示。
